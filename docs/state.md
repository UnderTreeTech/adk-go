在 ADK (Agent Development Kit) 的 Session 设计中，`appState`、`userState` 和 `sessionState` 代表了三个不同层级的状态存储，它们的作用域和生命周期各不相同。这种分层设计是为了满足不同场景下的数据共享和隔离需求。

### 1. AppState (应用级状态)

*   **作用域**: **全局共享**。在整个应用（Agent）范围内，所有用户、所有会话共享同一份数据。
*   **生命周期**: 只要应用存在，数据就一直存在（除非被显式删除或覆盖）。
*   **用途**:
    *   存储全局配置、系统常量。
    *   存储跨用户的统计信息（例如：总访问量、热门问题）。
    *   存储需要在不同用户之间同步的共享资源状态。
*   **代码中的体现**: 在 `session.go` 中，键通常以 `app:` 为前缀（如 `KeyPrefixApp`）。

### 2. UserState (用户级状态)

*   **作用域**: **用户级共享**。同一个 `UserID` 在同一个 `AppName` 下的所有会话共享同一份数据。
*   **生命周期**: 只要用户存在，数据就一直存在。
*   **用途**:
    *   存储用户的个人偏好设置（例如：语言偏好、主题颜色）。
    *   存储用户的长期记忆（例如：用户的历史订单、个人资料）。
    *   跨会话保持上下文（例如：用户在昨天会话中提到的名字，今天的新会话中依然记得）。
*   **代码中的体现**: 在 `session.go` 中，键通常以 `user:` 为前缀（如 `KeyPrefixUser`）。

### 3. SessionState (会话级状态)

*   **作用域**: **会话私有**。仅属于当前的 `SessionID`，不同会话之间完全隔离。
*   **生命周期**: 随着会话的创建而创建，随着会话的删除而销毁（或者过期）。
*   **用途**:
    *   存储当前对话的临时上下文（例如：当前讨论的话题、中间变量）。
    *   存储流程控制状态（例如：当前处于多轮对话的第几步）。
    *   存储不需要长期保存的临时数据。
*   **代码中的体现**: 没有特定前缀，直接存储在 Session 对象的 `state` 字段中。

### 总结与区别

| 特性 | AppState | UserState | SessionState |
| :--- | :--- | :--- | :--- |
| **共享范围** | 所有用户 | 单个用户的所有会话 | 单个会话 |
| **隔离性** | 最低 | 中等 | 最高 |
| **持久性** | 永久（直到被覆盖） | 永久（直到被覆盖） | 临时（随会话结束） |
| **典型场景** | 系统配置、全局统计 | 用户画像、历史记录 | 对话上下文、流程状态 |

### 举个例子

假设你在做一个**订票助手 Agent**：

1.  **AppState**: 存储当前的“票价表”或“剩余票数”。所有用户看到的票价应该是一样的。
2.  **UserState**: 存储用户的“常用联系人”或“会员等级”。用户 A 开启新会话时，助手依然知道他是 VIP 会员。
3.  **SessionState**: 存储用户“当前正在查询哪一天的票”。如果用户在同一个会话里改了日期，助手知道；但如果用户关掉窗口重新打开（新会话），助手就忘了他在查哪一天，需要重新询问。

这种设计使得 Agent 能够灵活地处理不同层级的记忆和上下文管理。
